## 2. 지금 절대 하면 안 되는 것 — 관리자 페이지 화면별 정리

토스 측이 명시한 수정 금지 항목 5개를, 실제로 **관리자 페이지(admin) 어느 화면에 있는지** 기준으로 정리했습니다. 하나카드 심사가 끝날 때까지는 아래 화면에서 해당 항목만 건드리지 마세요.

| 토스 금지 항목 | 관리자 페이지 화면 | 비고 |
|---|---|---|
| 사업자정보 (상호/대표자/사업자등록번호/주소/통신판매업신고번호) | **없음** — 관리자 페이지에서 수정하는 항목이 아닙니다 | 앱/웹 하단에 표시되는 이 정보는 코드에 고정값으로 들어 있어 개발자가 코드를 고쳐 배포해야만 바뀝니다. 관리자 화면에서 실수로 바꿀 방법 자체가 없으니, "이거 좀 수정해달라"는 요청도 심사 끝날 때까지는 개발팀에 넣지 마세요. |
| 전화번호 / 주소 | **매장 관리(`/store`)** 화면의 "전화번호", "주소" 입력란 | 사업자정보의 대표 전화번호·사업장 주소와는 별개로, 매장별 연락처·주소를 여기서 관리합니다. 고객에게 노출되는 정보이므로 심사 기간에는 변경하지 마세요. |
| 상품 카테고리 | **메뉴 관리(`/menu`)** 화면의 "카테고리 추가" 기능 | 카테고리를 새로 만들거나 구성을 바꾸는 것은 보류하세요. |
| 상품 품절처리 | **메뉴 관리(`/menu`)** 화면의 개별 메뉴 "품절/품절 해제" 버튼 | 오늘 재료 소진된 메뉴를 그때그때 품절 처리하는 **평소 운영은 그대로 하셔도 됩니다.** 토스가 문제 삼는 건 품절 "처리 방식·구성 자체"를 바꾸는 것(예: 품절 로직 변경, 숨김 처리 방식 변경)이지 일상적인 품절 토글이 아닌 것으로 해석됩니다. 다만 애매하면 심사 끝난 뒤로 미루는 게 안전합니다. |
| 비회원 결제수단 | **없음** — 관리자 페이지에 관련 설정 자체가 없음 | 신경 쓸 필요 없는 항목입니다. 이 설정은 개발/토스 쪽에서만 관리합니다. |

정리하면, 관리자가 실제로 조심할 화면은 **매장 관리(`/store`)의 전화번호/주소**와 **메뉴 관리(`/menu`)의 카테고리 구성**입니다. 나머지(사업자정보, 비회원 결제수단)는 관리자 화면에 노출조차 안 되어 있어 애초에 실수할 여지가 없습니다.

메뉴 가격 조정이나 신메뉴 추가, 일상적인 품절 처리 같은 통상적인 운영은 심사와 무관하므로 평소처럼 진행해도 됩니다.

## 3. 지금 확인/준비해두면 좋은 것

- **실제 판매 메뉴가 앱에 정상 노출되고 결제 가능한 상태**인지 한 번 확인 (테스트 상품만 있으면 안 됨)
- **환불/취소 정책 페이지**(`delivery.tacomole.kr/refund-policy`)가 실제 운영 정책과 일치하는지 확인
- **고객센터 연락처**가 실제로 응대 가능한 번호인지 확인
- 토스에서 추가 서류나 소명을 요청하는 이메일/알림톡이 오면 **1개월 이내 회신** (미회신 시 신청이 취소되어 처음부터 재신청해야 함)

  - 문의 예시: "상점아이디(MID) tacomom5cx, 하나카드 심사만 지연되고 있는데 사유 확인 부탁드립니다."
- 그 전에는 정상 대기 구간이므로 먼저 재촉 전화할 필요는 없습니다.

## 5. 심사 상태는 어디서 확인하나

토스페이먼츠 파트너센터 로그인 → **상점관리자 > 이용정보 > 결제 부가서비스** 탭에서 카드사별 심사 현황을 볼 수 있습니다. 며칠에 한 번 확인하는 정도로 충분합니다.

---

## 6. 심사가 다 끝나면(라이브 전환 시) 해야 할 일

관리자가 직접 할 일은 없고, **개발 담당자에게 "전체 승인완료"로 바뀌었다고 알려주기만 하면 됩니다.** 이후 키 교체·재배포는 개발 쪽에서 처리합니다 (상세: [`docs/toss_pay/README.md`](../toss_pay/README.md) 4~6절).

라이브 전환 후에는 실제 카드로 결제되고 실제 매출이 발생하므로, 전환 당일에는 결제가 정상적으로 되는지 한 번 직접 소액 주문으로 테스트해보는 것을 권장합니다.
