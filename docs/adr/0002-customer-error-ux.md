# ADR-0002. 고객 오류는 한글 인앱 안내로 통일한다

- 상태: **채택됨**
- 날짜: 2026-09-21
- 관련: `apps/backend/src/modules/orders/order-helpers.ts`, `apps/delivery-customer/src/app/store/[storeId]/order/checkout/page.tsx`

## 배경

배달앱은 서버 오류 메시지를 그대로 화면에 띄우는데, 주문·결제·세션·호출 경로 메시지가 영어로 남아 있었다.
표시 방식도 화면마다 갈렸다. 대부분은 인앱 UI(에러 배너·스켈레톤)를 쓰는데 9곳만 네이티브 `alert()`을 썼고,
Capacitor 앱에서는 URL이 붙은 시스템 다이얼로그로 떠서 유독 튀었다.

가장 나쁜 조합이 품절이었다. 고객이 메뉴를 담고 주소·연락처를 다 입력한 뒤 `주문하기`를 눌러야
`Menu is not available: 쇠고기 케사디야`라는 영어 alert을 보게 되고, **장바구니가 그대로라 다시 눌러도 같은 자리에서 막혔다.**

## 결정

**1. 고객이 닿는 서비스의 메시지만 한글로 바꾼다.**
`delivery-order`, `order-helpers`, `payments`(승인 경로), `sessions`, `calls`가 대상이다.
관리자 전용(계정 관리·브랜드 메뉴·메뉴 CRUD·POS 연동·Toss 내부 API)은 손대지 않는다.

**2. 주문할 수 없는 메뉴는 서버가 `menuId`를 함께 내려준다.**

```ts
throw new BadRequestException({
    statusCode: 400,
    code: 'MENU_UNAVAILABLE',
    message: `품절되었거나 판매하지 않는 메뉴입니다: ${menu.name}`,
    menuId: menu.id,
});
```

품절과 삭제(`Menu not found`) 둘 다 같은 `code`를 쓴다. 고객 입장에서는 같은 막다른 길이기 때문이다.
클라이언트는 이 `menuId`로 장바구니에서 해당 메뉴를 빼준다. 옵션 조합마다 항목이 따로 생기므로 같은 `menuId`를 전부 지운다.

**3. `alert()`을 쓰지 않는다.** 화면마다 맞는 인앱 UI로 안내한다.

| 위치 | 방식 |
|---|---|
| 체크아웃 | 결제 버튼 위 배너 |
| 로그인 | 소셜 버튼 위 배너 |
| 주소 입력 시트 / 주소 등록 | 확인 버튼 위 인라인 안내 |
| 장바구니 | 안내 문구가 이미 있어 버튼 비활성 조건만 추가 |
| 즐겨찾기 훅 | 띄울 UI가 없어 로그인 화면으로 이동 |

배너 스타일(`rounded-lg bg-red-50 px-3 py-2 text-sm text-red-600`)은 주소 등록 화면에 이미 있던 것을 따랐다.

## 결과

**얻은 것**
- 안내 방식이 한 가지로 통일됐다. Capacitor 앱에서 시스템 다이얼로그가 뜨지 않는다.
- 품절·삭제 메뉴가 자동으로 장바구니에서 빠져 재시도가 가능하다.

**잃은 것 / 남은 것**
- 백엔드 메시지에 한국어와 영어가 **섞인 상태로 남았다.** 관리자 화면은 여전히 영어를 본다.
  의도한 범위 제한이지만, 관리자도 결국 정리 대상이다.
- 토스트(`showErrorToast`)는 `isNative` 가드가 있어 웹에서 아무것도 뜨지 않는다.
  그래서 배너를 썼다. **웹 토스트 UI가 생기면** 즐겨찾기처럼 UI가 없는 곳도 토스트로 처리할 수 있다.
- 체크아웃 장바구니 정리는 E2E로 덮지 못했다. 결제 버튼이 로그인 게이트 뒤에 있는데
  delivery E2E 픽스처가 비로그인 전용이고, delivery-customer에는 유닛 테스트 러너가 없다.
  **서버 계약(`code`/`menuId`)만 백엔드 테스트로 고정했다.**
